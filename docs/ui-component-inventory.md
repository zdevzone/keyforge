## Library selection evidence

Shoogle confirmed `@uiarc/select`, `@uiarc/file-upload`, and `@uiarc/tooltip`. The shadcn registry CLI inspected and installed those plus `@uiarc/pagination`. Previously inspected UI Arc Combobox, Command Palette, Date Picker and Sortable Data Table remain in use. The current Settings extension installs UI Arc theme-switch, notification-center, tabs, checkbox, button and avatar registry files in `ui/src/components/arc`. The user-authorized ReUI `c-file-upload-2` is reused from the existing owned examples directory for profile images. Keep upstream sources and local integration notes in `ui/src/components/arc/README.md`; preserve the generated shadcn upgrade boundary.

## Shared behavior

Use Choice rather than choosing Select/Combobox independently on each page. Use ListPagination for complete local collections; preserve backend pagination for large operational datasets. Product table sorting occurs before slicing pages. Filter changes reset pagination, and shrinking local lists clamp to the last valid page. Action columns align right; dense icon actions have both tooltip text and accessible labels. Profile images fall back to initials on absence or load failure. Exports include the complete filtered report, not only the visible page.

## Plan issuance, preinstallation requests and payments (2026-10-15)

| Need | Existing system | Implemented pattern | Constraint / decision |
| --- | --- | --- | --- |
| Plans and pricing | Plan catalog plus existing product/plan price records | Plans editor adds Price (ETB) and single-option Currency Choice alongside duration, seats and entitlements | Birr input has up to two decimals; stored price is integer santim. Explicit plan prices override product fallback; zero is complimentary and missing price blocks issuance |
| Issue license | Shared focused dialog, Choice, fields and plan catalog | Existing-plan selection with a read-only terms, entitlements and price summary; UI Arc Already paid checkbox reveals shared PaymentFields | No issuance-time seat, expiry or entitlement overrides. Default is Unpaid; full-price receipt uses today's UTC date; complimentary issuance creates no receipt |
| Later payment | Existing sale/transaction history | Mark as paid dialog reuses PaymentFields: method Choice, editable UTC DateField and required transaction reference | Settles the outstanding balance of the existing sale; does not create a license or second sale. Existing partial payments/refunds/credits remain available |
| Request before installation | Shared Card, TextField, Choice, Button and feedback | Public `/request-license` entry and private `/license-request/:id#secret` status/retrieval page | No installation or operator account required; name/email are customer-provided and unverified. Explain saving the private link, no email sending, and normal activation after retrieval |
| Operator request queue | Existing table/filter/pagination and dialog patterns | License requests listing under Licenses, with search, status Choice, ListPagination and admin Issue license action | Copy public request link; inspect requested plan/contact data and open the same issuance dialog |
| Registered installation delivery | Existing authenticated in-app notifications | Notification and authenticated key retrieval through the dependent app; manual delivery remains a choice | Available, Retrieved, Manual and Failed have separate meanings; availability is not proof of receipt. Notifications never contain the raw key |

`PaymentFields` owns the common payment method/reference inputs and UTC date presentation: issuance displays today's date read-only, while later payment uses DateField. This keeps the two entry points consistent without suggesting payment controls license validation. The linked license, initial sale, optional receipt, request approval and delivery record commit atomically; UUID retries are idempotent, and stale plan/price previews are rejected. These behavior contracts are documented in `docs/license-sales.md`; screenshots alone do not establish them. Existing records, admin financial permissions, signing and validation boundaries are preserved.
